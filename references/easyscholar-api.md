# easyScholar 开放接口 · 字段说明与踩坑记录

> 来源：<https://www.easyscholar.cc/console/user/open> 的「期刊等级查询接口文档」，
> 2026 年 11 月 2 日由用户截图提供并逐条核对。
> 本文只记录**实测过或文档明确写明**的内容，不做推测。

## 一、接口

```
GET https://www.easyscholar.cc/open/getPublicationRank
    ?secretKey=<32 位密钥>&publicationName=<期刊全名>
```

按**刊名**查，不是按 ISSN。

## 二、文档明写的规则

| 规则 | 内容 |
|---|---|
| 费用 | **不与会员绑定，免费对所有用户开放**（不充会员也能用） |
| 限速 | **每秒最多 2 次请求** |
| 身份 | 只认 `secretKey`，不涉及登录，不挤占网页端登录态 |
| 密钥 | **无法更改**，泄露只能换账号 |
| 编码 | `publicationName` 要做 URL 编码，否则 `&` 等符号会拆坏参数 |
| 错误码 | `40002` = Key 错误 |

## 三、返回结构

```
{ "code": 200, "msg": "SUCCESS", "data": { "customRank": {...}, "officialRank": {...} } }
```

`officialRank` 下两个对象，**含义完全不同**：

| 键 | 含义 | 能不能依赖 |
|---|---|---|
| `all` | 全部 37 个字段 | **要读这个** |
| `select` | **用户在浏览器扩展里勾选的数据集** | **不能读** |

⚠️ **踩过的坑**：最初实现读的是 `select`，结果字段内容取决于用户插件里勾了什么。
换个人用、或者用户改了勾选，拿到的字段就变了，而且**不报错**。必须读 `all`。

`customRank` 是用户自己添加的数据集，与官方分区无关，不要用。

## 四、字段对照（附录 1）

### 中科院系列（四套，互不相同）

| 字段 | 含义 |
|---|---|
| **`xr`** | **新锐学术分区** |
| `xrTop` | 新锐学术 Top 分区 |
| `xrSmall` | 新锐学术小类分区 |
| `xrWarn` | 新锐学术预警 |
| `sciUp` | 中科院**升级版**分区 |
| `sciUpSmall` | 中科院升级版小类分区 |
| `sciUpTop` | 中科院升级版 Top 分区 |
| `sciBase` | 中科院**基础版**分区 |

⚠️ **重要**：「新锐」和「升级版」是**两套不同的东西**，`xr` ≠ `sciUp`。
本 skill 标准是「中科院《新锐期刊分区表》」，所以主列取 **`xr`**，`sciUp` 只作对照。

### JCR 与指标

| 字段 | 含义 |
|---|---|
| `sci` | SCI 分区 - JCR |
| `ssci` | SSCI 分区 - JCR |
| `sciif` | SCI 影响因子 - JCR |
| `sciif5` | SCI 五年影响因子 - JCR |
| `jci` | JCI 指数 - JCR |
| **`sciWarn`** | **中科院预警** |

⚠️ **踩过的坑**：预警字段是 `sciWarn`，**不是 `sciWarning`**。
写成 `sciWarning` 不会报错，只会一直返回空字符串，表现为「这些刊都没被预警」。
实测三本刊时预警列全空，就是这个原因。

### 其它常用

`esi`（ESI 学科分类）、`eii`（EI 检索）、`pku`（北大核心）、`cssci`（南大核心）、
`cscd`（中国科学引文数据库）、`ahci`（A&HCI）、`ccf`（中国计算机学会）、
`ajg`（ABS 期刊指南）、`ft50`、`utd24`、`fms`，以及各高校自定分级
（`swufe` `cufe` `uibe` `sdufe` `xdu` `swjtu` `ruc` `xmu` `sjtu` `fdu` `hhu` `scu` `cpu` `nju` `cqu` `xju` `cug` `zju` `cju` 等）。

## 五、取值格式

分区字段返回的是**带学科前缀的字符串**，不是纯数字：

```
"xr": "工程技术1区"
"sciUp": "物理与天体物理2区"
"sciBase": "工程技术3区"
```

要存成 `1` 到 `4`，必须用正则提取：`([1-4])\s*区`。
直接写进 Excel 会得到「工程技术1区」这种值，后面按分区筛会全部失效。

## 六、实测样本（2026 年 11 月 2 日）

| 期刊 | `xr` | `sciUp` | `sciBase` | `sci` | `sciif` | `sciif5` |
|---|---|---|---|---|---|---|
| Cement and Concrete Research | 工程技术1区 | 工程技术1区 | 工程技术1区 | Q1 | 14.0 | 15.7 |
| Ultrasonics | — | 物理与天体物理2区 | 物理3区 | Q1 | 4.8 | 4.7 |
| Applied Sciences | — | 综合性期刊4区 | 工程技术3区 | Q2 | 2.9 | 3.0 |

`xr` 列出现「—」的那两本，是当次请求还没取 `xr` 字段（修 bug 之前跑的），不是接口没有这个字段。

## 七、调试清单

接口出问题时按这个顺序查：

1. `code` 是不是 200，`40002` 就是 key 错
2. 读的是不是 `officialRank.all`，不是 `select`
3. 预警字段拼的 `sciWarn` 还是 `sciWarning`
4. 分区字段有没有做数字提取
5. 刊名是不是完整英文名（缩写、`(Print)` 后缀、全大写都可能匹配不上）
6. 有没有超过每秒 2 次
